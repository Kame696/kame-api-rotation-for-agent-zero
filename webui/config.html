KAME — API Rotation

Multi-key rotation with smart quarantine and an eternal carousel. The engine is intentionally opinionated — these are the only knobs.

Logging

How much KAME writes to the Docker log; the rotation algorithm is the same at every level. normal shows the pool count only when degraded, silent keeps KAME out of the log entirely, verbose adds heartbeat, timing, pool snapshot and a session summary, and verbose+errors also dumps the complete raw exception on every failure — use it to confirm KAME's classification (e.g. that a "daily-quota" line really carries a PerDay quota) is correct.

fingerprint is a hash like k3f9a1 — not your real key, so the secret never reaches the log. full writes the whole key; use only for local debugging.

Limits

How long to rest a key after a daily-quota or account / out-of-credit limit (any provider). KAME probes the key again after this interval — the provider's own retry hint is ignored for daily quotas since it is frequently wrong or misleading. Default 3600 (1h); range 1–86400.

Agent Zero stops a turn after N consecutive model outputs it cannot parse into a tool request, "to prevent further API charges". With a rotated pool that reason is much weaker — and A0 has itself moved the number (it was 2 in v2.4–v2.7, 5 in v2.8), so a settings file written by an older A0 keeps the tight 2 forever and one JSON-escaping slip ends the turn. KAME applies this as a floor, never a ceiling: effective = max(A0's setting, this). It is not a bypass — past this count A0's stop is left alone, so a model stuck in a formatting loop still cannot drain the pool. Default 5; set 0 to never interfere.
